# Grid  (type: 'grid')
Purpose:       An interactive data table: columns, sorting, selection, paging and virtualized scrolling.
Anatomy:       `.op-grid` (frame) > bulk bar (`.op-grid__bar`, when there are bulk actions/column menu) + `.op-grid__table[role=grid]` (focusable) > `.op-grid__header` (`__cell`, `is-sortable`, `is-sorted-asc/desc`) + `.op-grid__viewport` (scroll) >
               `.op-grid__spacer` + `.op-grid__rows` > `.op-grid__row[role=row]` > `.op-grid__cell[role=gridcell]`; + `Pagination` when `paging`. The bar and the pager live outside the `role=grid` part, which may only contain rows.
Config:        `store` (or `data`), `columns: [{field, header, width, flex, minWidth, align, sortable, hidden, renderer(value, rec, col), format, cls}]`,
               `selection: 'none'|'single'|'multi'` (single), `rowHeight` (measured from the CSS; fallback 32), `paging: false` (adds a Pagination),
               `emptyText`, `striped: false`, `ariaLabel`. `format`: a registered name (`money`, `date`, `number`, `percent`, `bool`) or a function.
Typing:        `Grid<T>`: `new Grid({ store })` takes `T` from a typed `Store<T>`, so `getSelection()`, `getStore()`, actions and renderers get `Model<T>` and `Column.field` autocompletes the keys. Untyped grids use `any`.
Bulk selection: `checkboxSelection: false` (a first column with checkboxes + "select all" in the header; implies multi and a row click toggles),
               `keepSelection: false` (the selection survives paging/filtering), `bulkActions: [{ text, icon, variant: 'default'|'danger', handler(records, grid) }]`
               (a bar above the header while something is selected: "N selected", the actions, "Select all N" (every filtered record), "Clear selection"),
               `rowActions: [{ text, icon, variant: 'default'|'danger', disabled(record), handler(record, grid) }]` + `rowActionsMode: 'menu'|'visible'`
               (`menu`, default: a "⋯" button at the end of the row opens a `Menu`; `visible`: one icon button per action, always shown, dimmed until the row is hovered/active/selected, with per-row `disabled`).
               The Grid owns the width and padding of the checkbox and action columns (the action column grows with the number of buttons). Shift+F10 / the menu key opens the active row's action menu, in both modes.
Reordering:    `reorderableColumns: false`: dragging a header (mouse/touch; 6 px threshold, so a plain click still sorts) shows a ghost under the pointer and a bar where the column will land; keyboard: Alt+←/→ with the focus on the header (headers without sorting get `tabindex=0`). Checkbox/action columns do not move and hidden ones keep their place. `moveColumn(field, before|null)`; event `column-move(field, from, to)` + `columns-change`.
Resizing:      `resizableColumns: false`: a handle on the end edge of each header; dragging changes the width live (respects the column's `minWidth`/`maxWidth`, at least 48 px), a double click goes back to a flexible width; keyboard: Alt+Shift+←/→ with the focus on the header (±16 px). `Column.resizable: false` locks a column. A flexible column starts from its shown width and becomes fixed. `setColumnWidth(field, px|undefined)`; event `column-resize(field, width)` (once, at the end of the drag) + `columns-change`; the width is part of `getColumnState` and of saved views. Works with `reorderableColumns` (Alt+arrows reorder, Alt+Shift+arrows resize).
Groups:        `Column.group: string` ("Identification", "Values"...), free per grid: a **band of labels** over the header (spans of neighboring columns of the same group; `groupHeaders: false` hides it) and, in the column menu, a **section per group** with a group checkbox (partial state and a `2/3` count), **chips** to filter the list by group, and a search that shows the whole group when it matches the group name; columns without a group go under "Other". `getColumnGroups()`, `setColumnGroupVisible(group, visible)` (one column always stays visible) + `columns-change`.
Columns:       `columnMenu: false` (a "Columns" button in the bar: a dropdown with search and one checkbox per column; the last visible column cannot be hidden).
P1 (not yet):  per-column filters in the header, inline editing, frozen columns, grouping — as plugins (`plugins: [...]`).
API:           `getSelection()` (returns `Model<T>[]`), `select(recOrIndex, {add})`, `deselectAll()`, `setStore`, `setColumns`, `refresh()`, `scrollToRow(i)`, `getStore()`, `focusRow(i)`, `selectAllFiltered()` (multi: every record that passes the filters, on every page; remote store: only the loaded page), `getColumnState()` / `setColumnState(state)` (`[{field, hidden, width}]`; the array order becomes the column order).
Events:        `select(selection)`, `row-click(rec, index, ev)`, `row-dblclick`, `sort(field, dir)`, `before-sort` (cancelable), `column-click`, `columns-change(state)`.
States:        `is-loading` (through `loading`, and automatic during `store.load`), `is-empty`; row `is-selected`, `is-active`.
Keyboard/ARIA: `role=grid` on `.op-grid__table`, with `aria-rowcount/aria-colcount`, `aria-activedescendant`; rows have `aria-rowindex`, `aria-selected`; headers `aria-sort`. ↑↓ move the active row, Home/End/PageUp/PageDown,
               Space selects (toggles with `checkboxSelection`; arrows only move the active row), Shift+↑↓ extends (multi), Ctrl/Cmd+A selects all (multi), Enter fires `row-activate`.
               The scrolling viewport is not a tab stop on purpose: the focusable `role=grid` moves the active row and scrolls it into view.
Virtualization: ALWAYS: only `visible + overscan` rows exist in the DOM (a reused pool); the total height comes from a spacer. 100,000 rows ≈ 30 row nodes.
Tokens:        `--op-grid-bg/border/row-height/header-bg/header-fg/row-hover-bg/row-selected-bg/row-stripe-bg/cell-padding-x`, `--op-grid-bar-bg`, `--op-grid-drop-width` (drop bar), `--op-grid-resizer-width` (resize handle), `--op-grid-group-bg/fg/tracking` (group band), `--op-grid-action-size/gap/idle-opacity/disabled-opacity`, `--op-grid-colmenu-width/height`.
Sandbox cases: checkbox + bulk actions + row actions, column menu (save/restore state), 10 rows, 100,000 rows (virtual), sorting, single/multi selection, local and simulated "remote" paging, custom renderer, empty, loading, dark theme.
Out of scope:  pivot, grouped columns, expandable rows, row drag (all P1/P2).
